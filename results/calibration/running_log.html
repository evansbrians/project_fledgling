Goal and verdict up front

Goal. Calibrate the radio-node network so we can tell which field (~50 m accuracy) a tagged bird is in, using RSSI. Cross-validate spatial accuracy on Blair’s calibration walk.

Verdict. The 50 m target is not reachable for every fix with RSSI from this network — the best honest, cross-validated overall median error is ~83 m (150 s windows, max-RSSI trilateration; accuracy plateaus there). But 50 m is reachable for about half of all fixes: at 150–180 s windows, fixes whose strongest node is ≥ −75 dBm have a median of ~48–49 m and make up ~48–51 % of all fixes. Shorter windows trade accuracy for temporal resolution (90 s → 95 m overall, 48 m on 52 % of fixes at ≥ −80 dBm; 60 s → 104 m). Earlier methods (NLS on 1 s windows, centroid+RF, Bayesian grid, Kierlivia global curve) hit 50 m on only ~11–19 % of fixes, so the max-RSSI windowed approach is both more accurate overall and far higher-coverage. The calibration “truth” carries position smear from window-averaging (the walker moves ~0.83 m/s × window); a deployed bird that stays put over a few minutes should smear less, so field accuracy may be better than these numbers.

The single biggest limiter is the data, not the algorithm: nodes are ~163 m apart, and even the closest detecting node is a median ~100–170 m from the bird because RSSI is a weak, noisy proxy for proximity here (the nearest node is the strongest only ~57 % of the time).

All errors below are ml_dist = haversine(predicted, GPS truth) in metres, under grouped 5-fold cross-validation (folds split by time-blocks so train/test events are temporally and spatially separated — an honest test). Two tag types (BOBO, EAME) are calibrated separately and pooled for reporting.

Data and pipeline

  • Source. oxbow.duckdb → raw detections for the 32 Blair calibration tags during the walk (2023-04-27, ~3.8 h), plus node_health GPS fixes.
  • Node positions. Median GPS per node over a ±7-day window. These are stable (max day-vs-window shift 6 m, within-node spread ≤ 11 m), so node movement is not a meaningful error source here.
  • Truth. Bad Elf handheld GPS, joined to detections by rounded second.
  • Events. A localizable event = one tag in one time-window detected by ≥ 3 nodes (not all at the noise floor). Time-windowing (8 s) averages RSSI per node to denoise and adds nodes per fix.

Quantity Value
Node nearest-neighbour spacing (median) 163 m

Nearest detecting node → bird (median, 8 s windows) ~100 m
Nearest node is also the strongest-RSSI node 57 % of events

Because RSSI only weakly tracks distance, multilateration and centroid methods are bounded well above 50 m on the typical fix; they only do well when a strong, nearby detection exists.

Interpretation by method

NLS multilateration (your baseline, methods 0–6 in calibration_blair.R). Fixing the small issues (units/joins) and running it under honest CV gives ~180–215 m median. Inverse-distance² weighting and restricting to the strongest nodes help; bias/weight tweaks help marginally. It is fundamentally limited by the flat RSSI–distance curve (fitted c ≈ 0.009, i.e. RSSI near the floor beyond ~300 m), so far/weak nodes contribute almost no positional information yet add noise.

RSSI-weighted centroid. A simple, robust estimator. Raising the weight exponent pushes it toward “snap to the strongest node” and improves median to ~160 m. Slightly better than trilateration and far more stable (no NLS non-convergence).

RF residual correction (best). Keep the weighted centroid, then train a random forest to predict the systematic offset (truth − centroid) from event geometry (centroid position, node count, strongest-node coordinates and RSSI, signal spread). This corrects the centroid’s inward bias and the predictable geometry-dependent errors → 128 m median, the best overall. It generalises under block CV because it is anchored to physical node positions; the RF only learns a bounded correction.

Direct ML / fingerprinting (failed). Mapping the full per-node RSSI vector directly to location with RF/kNN/HGB collapses to ~680 m under honest block CV (it essentially predicts the mean location), even though leaky random-CV looks fine at ~160 m. Reason: Blair’s walk is a single, non-repeating path, so a held-out segment’s RSSI signature has no nearby training analogue. Fingerprinting needs a dense grid walk with revisits — a data-collection change, not an algorithm change.

Bayesian grid (posterior mean). With the weak curve the posterior is broad and multi-modal, so its mean is dragged toward the grid centre → 241 m. The MAP cell would help somewhat but cannot overcome the weak likelihood.

Global curve from Kierlivia, applied to Blair (cross-dataset test)

A cleaner generalisation test than within-Blair CV: fit one global RSSI–distance curve from Kierlivia’s controlled data (only tags perpendicular to the node, 2 m height, pooled), then use it to multilaterate Blair’s 2 m tags. Train and test are fully independent datasets/years, so no cross-validation is needed.

The curves are very different. Kierlivia (controlled, 0–199 m, perpendicular) is steep with a high floor: a=-88.6, b=-44.9, c=0.049 (e-fold 20 m). Blair’s own 2 m curve is flat: a=-103.0, b=-33.7, c=0.008 (e-fold 122 m). The controlled setup produces cleaner, stronger short-range signal.

Strongest-RSSI filter on the valid-node Kierlivia result: ≥ −75 → 68 m, ≥ −72 → 56 m, ≥ −70 → 46 m (n = 250).

Interpretation.

  • Using all nodes, the global Kierlivia curve is essentially tied with Blair’s own curve (197 vs 188 m). Both are dragged down by weak, far detections — the curve choice barely matters when most nodes carry little positional information.
  • The Kierlivia curve’s high noise floor (−88.6 dBm) is the catch: most of Blair’s real detections are weaker than that, so they fall outside the curve’s valid domain and can only be read as “far”. Only ~8 % of Blair’s 2 m fixes have ≥ 3 nodes stronger than −88.6 dBm.
  • On exactly those valid, close-range fixes the global curve does well — 95 m median, and ~46 m for the strongest fixes — and this holds across independent datasets, which is encouraging evidence the close-range physics transfers.
  • Practical implication: a Kierlivia-style controlled curve is a good short-range model. To use it network-wide you’d want to extend the controlled stops to longer distances (so the curve’s floor matches Blair’s real detections), or pair it with the centroid+RF estimator for weak fixes.

Combining Blair + Martin (best method, predicted to Blair)

Applied the best method (RSSI-weighted centroid + RF residual) with Martin’s 2022 calibration added as training augmentation, always testing on held-out Blair GPS points (grouped 5-fold CV). Martin is a separate dataset: ~28-node subset network (25 of 28 nodes shared with Blair), single tag height, its own 16 tags, a year earlier. Martin’s node positions come from Martin-era node_health; all features are built in Blair’s local metre frame so the two are comparable.

Combined data + 500 m geometry gate (trilateration)

Took the m1 trilateration (1 s events, inverse-dist² weights, top-k strong nodes), pooled Martin + Blair for both the curve and the events, and added a geometry gate: keep only events with ≥ 3 detecting nodes within 500 m of the strongest-RSSI node, localizing with exactly those within-500 m nodes. Honest grouped 5-fold CV (Martin 2022 / Blair 2023 never share a time-block).

Interpretation. The 500 m gate does not help — Blair median ~202 m is worse than the ungated m1 (~176 m) and far behind the best method (128 m). The gate’s intent (guarantee a local cluster of nodes) doesn’t address the real limiter: RSSI is a noisy proxy for distance, and the strongest-RSSI “anchor” is itself a median ~218 m from the bird, so a 500 m radius around it still admits a broad, biased node cluster. Trilateration accuracy is bounded by RSSI noise, not by the presence of far outlier nodes. (Files: 13_combined_trilat_gated.py, combined_gated_trilat_results.csv.)

This is the best result of the whole study. Overall median 104 m beats the previous best (centroid + RF residual, 128 m), and — crucially for the 50 m goal — ~44 % of fixes reach ~52 m (≥ −80 dBm) and 30 % reach ~39 m, far more coverage than any earlier method (which hit 50 m on only ~11–19 % of fixes).

Why the jump. Taking the maximum RSSI per node over a full minute captures that node’s closest-approach beacon and rejects the many weak, multipath-degraded packets that drag the mean down. It effectively denoises by “best of window” rather than “average of window,” sharpening the RSSI–distance relationship exactly where it matters (near nodes).

One caveat. Truth here is the 60 s average location; at 3 km/h the walker covers ~50 m in 60 s, so ~±25 m of position smear is baked into the “truth.” A deployed, slower-moving bird would smear less, so real-world accuracy with this method could be better than these numbers suggest. (Files: 14_blair_60s_maxrssi.py, blair_60s_maxrssi_results.csv.)

Accuracy improves with window length up to ~150 s, then plateaus (150 s → 82.8 m, 180 s → 83.5 m). A longer window gives each node more chances to log its closest-approach beacon (better max-RSSI denoising) and pulls in more nodes per fix; once every node has caught its closest beacon, extending further adds nothing, leaving a residual ~83 m floor set by RSSI noise and node geometry.

The trade-offs of longer windows are (a) fewer, temporally coarser fixes and (b) more position smear in the calibration truth (the walker covers ~0.83 m/s × W). The latter matters less for a deployed bird that stays in one area over a few minutes, so for survival-model use longer windows are reasonable.

Choosing WINDOW_S: 150 s is the accuracy-optimal plateau (overall 83 m; with the strongest-node ≥ −75 dBm filter, ~48 m on ~48 % of fixes; 180 s → 49 m on 51 %). 90 s balances accuracy with temporal resolution (95 m; 48 m on 52 % at ≥ −80 dBm). 60 s for the finest timing (104 m). Note the ≥ −80 dBm median rises slightly at very long windows because the wider net admits more marginal far-but-detected nodes; the ≥ −75 dBm filter is more stable. final_localization.R exposes WINDOW_S (default 90 s; set 150 s to minimise median error for slow/stationary birds). Successes and limitations

Successes

  • Reproduced and stress-tested your pipeline under honest cross-validation.
  • Identified the best estimator (centroid + RF residual), beating raw multilateration by ~90 m median.
  • Showed a practical confidence filter that meets the 50 m goal for a well-defined, sizeable subset of fixes, and quantified the trade-off.

Limitations

  • Overall (all-fix) 50 m is not achievable with this RSSI data; ~128 m is the honest floor.
  • Calibrated and tested on a single walk/day; year-to-year node and vegetation changes are not captured.
  • Fingerprinting (often the most accurate approach elsewhere) is unavailable until a dense, repeated grid walk exists.

Suggested next steps (if higher accuracy is required)

  1. Densify nodes in priority fields (target ≤ 80–100 m spacing).
  2. Collect a fingerprinting grid walk (lawn-mower pattern with revisits, multiple passes) — this unlocks ML fingerprinting and likely sub-50 m.
  3. Per-node calibration / antenna-orientation controls to reduce the RSSI noise that makes the nearest node the strongest only ~57 % of the time.
  4. Combine Blair + Kierlivia for the RSSI–distance curve (curve-based methods only; it will not change the centroid + RF result much).
